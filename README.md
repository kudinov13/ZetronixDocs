# ZenzaDocs Server

Сервер подписок и лицензирования для приложения ZenzaDocs.

## Возможности

- Генерация RSA-подписанных лицензионных ключей
- Онлайн-активация лицензий на компьютерах клиентов
- Сбор отчётов об использовании токенов
- Еженедельные отчёты по клиентам в рублях
- Управление подписками (продление, отзыв)
- Безлимитные лицензии для сотрудников

## Установка

### 1. Установите PostgreSQL

```bash
# Windows: скачайте с https://www.postgresql.org/download/windows/
# Linux: sudo apt install postgresql
```

### 2. Создайте базу данных

```sql
CREATE DATABASE zenzadocs;
CREATE USER zenza WITH PASSWORD 'zenza_password';
GRANT ALL PRIVILEGES ON DATABASE zenzadocs TO zenza;
```

### 3. Настройте окружение

```bash
cp .env.example .env
# Отредактируйте .env — укажите параметры БД и JWT_SECRET
```

### 4. Установите зависимости

```bash
npm install
```

### 5. Сгенерируйте RSA ключи

```bash
npm run generate-keys
```

Это создаст:
- `keys/private_key.pem` — приватный ключ (ХРАНИТЬ В СЕКРЕТЕ)
- `keys/public_key.pem` — публичный ключ (встраивается в приложение)

**Важно:** скопируйте содержимое `keys/public_key.pem` в файл приложения
`src/lib/license.ts` (замените `PUBLIC_KEY_PLACEHOLDER`).

### 6. Запустите миграцию

```bash
npm run migrate
```

### 7. Запустите сервер

```bash
npm start
```

Сервер будет доступен на `http://localhost:3000`.

## Генерация лицензионных ключей

### Корпоративный клиент (15-20к/мес, годовая подписка)

```bash
node src/generate-license.js --customer="ООО СтройИнвест" --plan=large --days=365
```

### Малый ИП (2-2.5к/мес, месячная подписка)

```bash
node src/generate-license.js --customer="ИП Иванов И.И." --plan=small --days=30
```

### Сотрудник (бесплатный безлимит)

```bash
node src/generate-license.js --customer="Сотрудник Пётр" --plan=staff --unlimited
```

### Пробный период (14 дней)

```bash
node src/generate-license.js --customer="ООО Тест" --plan=trial --days=14
```

## Еженедельный отчёт

```bash
npm run report
```

Выводит:
- общее количество активных клиентов
- потраченные токены и стоимость в рублях за неделю и месяц
- детализацию по каждому клиенту
- клиентов с истекающей подпиской (≤7 дней)
- клиентов с истекшей подпиской

## API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/health` | Проверка здоровья сервера |
| POST | `/api/license/activate` | Активация лицензии |
| POST | `/api/usage/report` | Отчёт об использовании токенов |
| POST | `/api/admin/login` | Вход администратора |
| GET | `/api/admin/report` | Еженедельный отчёт (JWT) |
| GET | `/api/admin/licenses` | Список лицензий (JWT) |
| POST | `/api/admin/revoke` | Отзыв лицензии (JWT) |

## Архитектура лицензирования

```
1. Сервер генерирует RSA-ключи (один раз)
2. Сервер создаёт лицензию:
   - payload (JSON): customer, plan, expiry, unlimited, keyId
   - подпись: RSA-SHA256(payload)
   - ключ: ZENZA1.<base64(payload)>.<base64(подпись)>
3. Клиент вводит ключ в приложении
4. Приложение проверяет подпись публичным ключом
5. При наличии интернета — регистрирует активацию на сервере
6. Приложение работает офлайн до истечения срока
7. Приложение периодически отправляет отчёты о токенах на сервер
8. Сервер формирует еженедельные отчёты для владельца
```

## Безопасность

- Приватный RSA-ключ никогда не покидает сервер
- Публичный ключ встроен в приложение — подделать подпись невозможно
- Лицензии можно отзывать через админ-панель сервера
- JWT-токены для админ-доступа истекают через 24 часа
- Пароль администратора хэшируется (bcrypt в продакшене)
